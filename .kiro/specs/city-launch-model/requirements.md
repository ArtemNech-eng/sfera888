# Requirements Document — City Launch Model

## Introduction

Маркетплейс `chestnye-mastera.ru` изначально сделан под несколько городов ради SEO,
но по факту мастера есть только в **Краснодаре**. Бизнес-стратегия: **копить SEO-вес
по городам заранее**, а операционный запуск (мастера, приём заявок) открывать в городе
по факту появления трафика/спроса и набора мастеров.

Фича вводит явную модель «состояния города» на маркетплейсе, чтобы разграничить
операционно запущенные города и «пре-лонч/SEO» города — без «каши» и без вредных для
SEO тонких страниц.

## Glossary

- **City**: строка таблицы `cities` (`lib/db/src/schema/settings.ts`).
- **is_active**: город доступен в системе (используется CRM/PWA/маркетплейсом).
- **is_geo_covered**: город входит в целевой SEO-набор (гео-набор `GEO_COVERED_CITY_SLUGS`).
- **is_launched**: город операционно запущен — есть мастера, полный опыт маркетплейса.
- **Launched_City**: `is_launched = true`.
- **Prelaunch_City**: `is_geo_covered = true AND is_launched = false`.
- **Service_City_Page**: страница `/[serviceSlug]/[citySlug]` (длинный хвост «услуга×город»).
- **City_Hub**: контентная страница города `/goroda/[city]` (community-раздел «Соседи»).
- **Waitlist_Lead**: заявка клиента из пре-лонч города (лист ожидания, спрос).

## Requirements

### Requirement 1: Явный флаг операционного запуска города

**User Story:** Как оператор платформы, я хочу помечать город как «запущенный»
отдельным флагом, чтобы публичный маркетплейс отличал города с мастерами от городов,
которые пока только копят SEO-вес.

#### Acceptance Criteria
1. У `cities` есть колонка `is_launched boolean NOT NULL DEFAULT false`.
2. Миграция аддитивна и идемпотентна (`ADD COLUMN IF NOT EXISTS`), не ломает CRM/PWA.
3. На старте `is_launched = true` проставляется Краснодару идемпотентно при загрузке api-server.
4. Публичный DTO города (`/api/marketplace/cities`, `/service-city`) отдаёт `isLaunched`.

### Requirement 2: Длинный хвост «услуга×город» — только для запущенных городов

**User Story:** Как SEO-владелец, я не хочу индексировать пустые страницы «услуга×город»
в городах без мастеров, чтобы не получить тонкий/дорвейный контент.

#### Acceptance Criteria
1. `sitemap.xml` включает пары `/[service]/[city]` **только** для Launched_City.
2. Service_City_Page для Prelaunch_City отдаёт `robots: noindex, follow`.
3. Service_City_Page для Launched_City работает как прежде (индексируется, каталог мастеров).

### Requirement 3: Честный пре-лонч экран (лист ожидания + набор мастеров)

**User Story:** Как посетитель из пре-лонч города, я хочу видеть честную страницу
(без обещания «мастер перезвонит»), чтобы понимать, что город ещё открывается.

#### Acceptance Criteria
1. Для Prelaunch_City Service_City_Page показывает: лист ожидания клиента + блок набора
   мастеров (ссылка `https://sfera-master.ru/masteram`), без каталога мастеров.
2. Заявка из листа ожидания сохраняется как обычный лид с пометкой источника (Waitlist_Lead).
3. Launched_City не затрагивается (полный опыт сохраняется).

### Requirement 4: Копление веса через контентные хабы

**User Story:** Как SEO-владелец, я хочу, чтобы пре-лонч города копили вес через
контентные страницы, а не через пустую матрицу услуг.

#### Acceptance Criteria
1. City_Hub `/goroda/[city]` для гео-набора остаётся индексируемым и в sitemap.
2. Пре-лонч Service_City_Page ссылается на свой City_Hub и калькулятор.

### Requirement 5: Консистентность внутренних ссылок

**User Story:** Как посетитель, я не хочу попадать по ссылкам в пустые каталоги городов.

#### Acceptance Criteria
1. Футер строит колонку «Города» из Launched_City (деградирует к «Все города» при сбое API).
2. Рейл городов на `/uslugi` показывает только Launched_City.
3. Нет захардкоженных ссылок на города вне каталога (Москва/СПб/Екб/Новосибирск удалены).

### Requirement 6: Переключение города в запуск

**User Story:** Как оператор, я хочу открыть город одним действием, когда набраны мастера.

#### Acceptance Criteria
1. `UPDATE cities SET is_launched = true WHERE slug = '<slug>'` открывает город без релиза кода.
2. После этого автоматически: каталог мастеров, обычная форма заявки, матрица «услуга×город»,
   попадание пар в sitemap.
