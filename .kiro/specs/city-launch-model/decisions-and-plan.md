# City Launch Model — решения и план

> Статус: **согласовано, ожидает реализации**. Черновик заметки, чтобы зафиксировать
> договорённости и не потерять контекст перед стартом разработки.

## Контекст

Маркетплейс `chestnye-mastera.ru` изначально сделан под несколько городов ради SEO.
Реально мастера есть только в **Краснодаре**. Стратегия: **копить SEO-вес по городам
заранее**, а мастеров запускать в городе тогда, когда там появится реальный трафик/спрос.
Главная цель — сделать это чисто, без «каши».

### Находки по коду

- Города берутся из БД (таблица `cities`, схема `lib/db/src/schema/settings.ts`).
- Публичный каталог/заявки жёстко завязаны на `is_active=true`:
  `/api/marketplace/cities`, `/api/marketplace/service-city/...`. Для неактивного города
  API отдаёт пусто → страница `app/[serviceSlug]/[citySlug]/page.tsx` делает `notFound()`
  + `robots noindex`. **Значит незапущенные города сейчас НЕ копят вес (404).**
- Уже есть флаг `is_geo_covered` — целевой SEO-набор. В коде это узкий шортлист из 4 городов
  Юга (`GEO_COVERED_CITY_SLUGS` в `artifacts/api-server/src/lib/communitySeed.ts`).
- Гео-сообщество `/goroda/[city]` и community-sitemap гейтятся по `is_geo_covered` (+ `is_active`).
- Миграции схемы `cities` накатываются идемпотентно при старте
  (`applyCommunityBaseline()` в `artifacts/api-server/src/index.ts`, `ADD COLUMN IF NOT EXISTS`).
- В `Footer.tsx` захардкожены Москва/СПб/Екатеринбург/Новосибирск со ссылками на пустой
  каталог — это надо убрать.

## Модель: два независимых флага на город

| Состояние | Флаги | Что показываем | Индексация |
|---|---|---|---|
| **Запущен** | `is_launched=true` | Полный опыт: каталог мастеров, кейсы, обычная форма заявки («мастер перезвонит») | Да |
| **Пре-лонч / SEO** | `is_geo_covered=true`, `is_launched=false` | Хаб города + контент (гайд цен, калькулятор, дизайн, кейсы). CTA: лист ожидания клиента + набор мастеров | Да |
| **Скрыт** | ни то, ни другое | — | Нет (`noindex`/404) |

## Подтверждённые решения

1. **CTA в пре-лонч городах** — связка «лист ожидания клиента + набор мастеров»
   («Работайте с нами в {городе}»). Трафик конвертируем не в мёртвые лиды, а в мастеров
   и доказательство спроса. Пришёл трафик → набрали мастеров → `is_launched=true` → город открыт.
2. **Начинаем с шортлиста**, а не со всех городов РФ.
3. **⚠️ КЛЮЧЕВОЕ (не забыть при разработке):** до запуска города индексируем **только хаб
   города + контентные страницы**. Полную матрицу «услуга×город» (длинный хвост) раскрываем
   **только на запуске**, когда есть мастера и живой контент. Это главный барьер от
   тонкого/дорвейного контента.

## Шортлист (стартовый SEO-набор)

Уже зашит в коде (`GEO_COVERED_CITY_SLUGS`), 4 города Юга:

- **Краснодар** (`krasnodar`) — запущен (`is_launched=true`)
- **Ростов-на-Дону** (`rostov-na-donu`) — пре-лонч / SEO
- **Волгоград** (`volgograd`) — пре-лонч / SEO
- **Ставрополь** (`stavropol`) — пре-лонч / SEO

## Поэтапный план реализации

### Фаза 1 — модель данных + гейтинг
- Добавить флаг `is_launched` в схему `cities` (`lib/db/src/schema/settings.ts`) +
  идемпотентная миграция при старте (`api-server/src/index.ts`, зеркало в `migrations/`).
  Проставить `is_launched=true` только Краснодару.
- Ввести понятие «состояние города» в marketplace-API (`/cities`, `/service-city`):
  различать launched vs pre-launch, а не только `is_active`.

### Фаза 2 — пре-лонч страницы + честный CTA
- Хаб `/goroda/[city]` и `/[serviceSlug]/[citySlug]`: для пре-лонч городов рендерить
  контентный режим (не 404), индексируемый.
- `LeadForm`: режим «лист ожидания» для клиента + блок набора мастеров. В проекте уже есть
  задел (`design_waitlist`, `city_not_found`).
- Ограничить длинный хвост «услуга×город» только запущенными городами (решение №3).

### Фаза 3 — чистка и консистентность
- Убрать захардкоженные города из `Footer.tsx` — строить из данных.
- Проверить fallback на `/mastera`, `/uslugi` и `sitemap` (уже завязаны на активные города).
- Оформить полноценную спеку `.kiro/specs/city-launch-model/` (requirements/design/tasks).

## Что происходит при запуске нового города

1. В городе набрано достаточно мастеров (спрос доказан трафиком).
2. Ставим `is_launched=true`.
3. Автоматически: открывается каталог мастеров, включается обычная форма заявки,
   раскрывается матрица «услуга×город».
