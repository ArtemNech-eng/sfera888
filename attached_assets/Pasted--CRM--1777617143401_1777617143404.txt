Добавь в CRM новый блок на главном дашборде:

«Что делать сейчас»
и подпись:
«Задачи, требующие вашего действия»

Очень важно:
Сейчас при клике на задачу происходит переход в другой раздел (например, в карточку заказа).
Так больше делать не нужно.

Новая логика:
при нажатии на задачу должен открываться POPUP / MODAL
с оформленной карточкой этой задачи,
с описанием,
с контекстом,
и с возможностью решить задачу ПРЯМО В ЭТОМ POPUP,
без перехода на другую вкладку или страницу.

Работаем в текущем проекте:
- backend: Node.js + TypeScript + Express + Drizzle + PostgreSQL
- frontend: React + Vite + TypeScript
- иконки: lucide-react
- стили: в текущем стиле CRM / дашборда
- весь интерфейс на русском
- без эмодзи, использовать только иконки

1. НОВЫЙ БЛОК НА ДАШБОРДЕ
==================================================

Добавить отдельный блок на странице Dashboard:

Заголовок:
«Что делать сейчас»

Подзаголовок:
«Задачи, требующие вашего действия»

чтобы админ видел его сразу.

Блок должен содержать:

1. Сводку по задачам:
- Критичные
- Высокий приоритет
- Средний приоритет
- Низкий приоритет
- Выполнено сегодня

2. Список задач:
каждая задача — отдельная строка/карточка

Пример списка:

- Мастер не откликнулся по заказу #151
- Баланс Avito ниже 1000 ₽
- Мастер заблокирован и требует проверки

7. КНОПКИ ДЕЙСТВИЙ В POPUP
==================================================

Для каждого типа задачи — свои действия.

--------------------------------------------------
Тип no_estimate
--------------------------------------------------
Показывать:
- заказ
- мастер
- сколько часов без сметы
- ожидаемая комиссия

Действия:
- Написать мастеру
- Позвонить мастеру
- Переназначить
- Отменить заказ
- Пометить задачу выполненной

--------------------------------------------------
Тип no_payment
--------------------------------------------------
Показывать:
- заказ
- мастер
- клиент
- сколько часов без оплаты
- сумма предоплаты
- сумма риска

Действия:
- Напомнить мастеру
- Позвонить клиенту
- Вернуть в пул
- Отменить заказ
- Пометить выполненной

--------------------------------------------------
Тип no_master_response
--------------------------------------------------
Действия:
- Написать мастеру
- Повторно разослать
- Назначить вручную
- Отменить заказ

--------------------------------------------------
Тип blocked_master
--------------------------------------------------
Показывать:
- мастер
- причина блокировки
- проблемный заказ
- сколько часов висит

Действия:
- Написать мастеру
- Разблокировать вручную
- Открыть проблемный заказ (но не как переход, а вложенная мини-карточка)
- Пометить как проверено

--------------------------------------------------
Тип low_avito_balance
--------------------------------------------------
Показывать:
- текущий баланс
- рекомендуемый минимальный баланс
- средний расход в день

Действия:
- Обновить баланс вручную прямо в popup
- Пометить как решено

--------------------------------------------------
Тип possible_bypass / conflict
--------------------------------------------------
Показывать:
- заказ
- мастер
- краткий summary
- риск
- последние сообщения / сигналы

Действия:
- Написать мастеру
- Заблокировать мастера
- Перевести заказ в ручной контроль
- Пометить как проверено

8. ДЕЙСТВИЯ ДОЛЖНЫ РАБОТАТЬ ПРЯМО ИЗ POPUP
==================================================

Без переходов.

Если нажали:
- Написать мастеру → открыть мини-форму сообщения в popup
- Переназначить → открыть mini selector мастеров в popup
- Обновить баланс → input + save прямо в popup
- Отменить заказ → confirm прямо в popup
- Вернуть в пул → confirm прямо в popup
- Разблокировать мастера → confirm прямо в popup

После выполнения действия:
- обновить popup
- обновить список задач
- обновить summary на дашборде
- показать toast «Действие выполнено»

9. НУЖНЫЕ BACKEND ENDPOINTS
==================================================

Создай endpoint для получения одной задачи:

GET /api/dashboard/action-items/:id

Возвращает полную карточку задачи:
{
  ...task,
  timeline: [],
  context: {},
  related: {},
  notes: []
}

Создай универсальный endpoint для действий:

POST /api/dashboard/action-items/:id/action

Body:
{
  "action": "message_master" | "call_client" | "reassign" | "cancel_order" | "return_to_pool" | "resolve" | "dismiss" | "update_balance" | "manual_unblock",
  "payload": {}
}

Endpoint сам:
- валидирует действие
- вызывает нужную бизнес-логику
- возвращает обновлённую задачу
