# Fix — мастера «выбрасывает» со страницы подписания договора (новый кабинет)

> [!WARNING]
> **Симптом.** В новом кабинете мастера (`chestnye-mastera.ru/cabinet`) вверху висит плашка «Подписать договор». Мастер по ней переходит — и через несколько секунд его выбрасывает обратно на список заказов. Прочитать и подписать договор не получается.
>
> **Причина.** Поллинг `/auth/me` на странице подписания делал редирект при `status === "active"`, а у только что зарегистрированного мастера статус `active` стоит по умолчанию.
>
> **Фикс.** Гейтим редирект на наличие `contractSignedAt` — теперь он срабатывает только после подписания.

## Background

### Для тех, кто не в контексте

«Честные Мастера» — платформа, где мастера получают заявки на ремонт. У мастера есть личный **кабинет** — раньше это было отдельное PWA (`master-pwa`), сейчас его переносят в единый кабинет на маркетплейсе (Next.js, каталог `artifacts/marketplace/app/cabinet`). Кабинет живёт под `/cabinet/*`, а его серверный `layout.tsx` — это auth-гард: он читает мастера из сессионной cookie и, если мастера нет, редиректит на `/login`.

Чтобы получать заказы, мастер должен подписать **договор-оферту**: прочитать текст, ввести паспортные данные, загрузить фото паспорта и нажать «Подписать». За это отвечает страница `/cabinet/pending-contract` (компонент `PendingContractView`).

Важны два поля мастера в БД (`masters`):

| Поле | Смысл |
|---|---|
| `status` | enum `active \| suspended \| inactive \| pending_contract`. Значение **по умолчанию — `active`**. |
| `contractSignedAt` | момент подписания договора; `null`, пока не подписан. |

### Жизненный цикл статуса вокруг договора

Это ключ к пониманию бага:

- Самозапись мастера (`POST /api/master-pwa/auth/register`) создаёт запись сразу со `status = "active"` и `contractSignedAt = null`.
- Подписание (`POST /api/contract/sign`) ставит `contractSignedAt = now` и переводит статус в **`pending_contract`** — «ждём подтверждения админом».
- Дальше админ (или авто-активация при следующем логине) возвращает статус в `active`.

То есть переход `pending_contract → active` при уже проставленном `contractSignedAt` — это и есть сигнал «мастера активировали, пускаем в кабинет».

### Узкий контекст: где именно ломалось

В `layout.tsx` мастеру без договора показывается **некритичная плашка-подсказка** со ссылкой на `/cabinet/pending-contract` (заявки при этом можно брать и без договора — оператор просто увидит пометку «Без договора»). Сама плашка исправна. Проблема — в поллинге внутри `PendingContractView`.

## Intuition

Поллинг раз в 8 секунд опрашивает `/auth/me`, чтобы «поймать» момент активации мастера админом и сразу увести его в кабинет. Но условие редиректа было слишком широким:

> [!CAUTION]
> Редирект срабатывал при **любом** `status === "active"`. А `active` — это статус по умолчанию у любого мастера, в том числе у того, кто ещё и не думал подписывать договор.

Разберём на игрушечном таймлайне мастера, который только что зарегистрировался (`status=active`, `contractSignedAt=null`):

1. `t=0с` — открывает `/cabinet/pending-contract`, начинает читать договор.
2. `t=8с` — срабатывает первый тик поллинга. `me()` возвращает `status="active"` → `router.push("/cabinet")`.
3. Мастера уносит на `/cabinet/orders`. Подписать он физически не успевает — форма из 4 шагов не проходится за 8 секунд.

Правильная интуиция: редирект «в кабинет» имеет смысл **только если договор уже подписан** — тогда `active` действительно означает «админ подтвердил». До подписания мастер обязан оставаться на странице.

## Code

Весь фикс — в одном `useEffect` (`artifacts/marketplace/app/cabinet/pending-contract/PendingContractView.tsx`). Добавлено одно условие `m.contractSignedAt &&` перед редиректом.

```diff
- // Poll auth/me every 8 seconds to detect admin activation
  useEffect(() => {
    const interval = setInterval(() => {
      cabinetAuth.me().then((me) => {
        const m = me as { status?: string; contractSignedAt?: string | null };
-       if (m.status === "active") {
+       if (m.contractSignedAt && m.status === "active") {
          router.push("/cabinet");
          router.refresh();
        }
        if (m.contractSignedAt && step !== "done") setStepRaw("done");
      }).catch(() => {});
    }, 8_000);
    return () => clearInterval(interval);
  }, [step, router]);
```

Почему этого достаточно — разбор по состояниям мастера:

| Мастер | `contractSignedAt` | `status` | Поведение после фикса |
|---|---|---|---|
| Только зарегистрировался | `null` | `active` | Остаётся на странице, читает и подписывает ✅ |
| Только что подписал | задан | `pending_contract` | Остаётся на экране «Договор подписан», ждёт активации ✅ |
| Подписал и активирован | задан | `active` | Авто-редирект в `/cabinet` (как и задумано) ✅ |

Логика теперь совпадает со старым `master-pwa`, где страница договора вообще не делала форс-редиректа, а только опрашивала `/auth/me` через `refresh()`.

## Verification

> [!NOTE]
> Изменение — точечный guard в одном `useEffect`, без новых импортов и символов; типобезопасно по построению (`m` уже типизирован как `{ status?: string; contractSignedAt?: string | null }`).

Автоматически: репозиторий на момент правки не имеет установленных `node_modules` (полный workspace-install тяжёлый из-за `minimumReleaseAge` в pnpm), поэтому прогон `tsc`/`next build` в песочнице не выполнялся. Правка проверена чтением: она не вводит новых типов и переиспользует уже объявленные поля.

Ручное QA (рекомендую прогнать перед мержем):

1. Зарегистрировать нового мастера (или взять мастера с `contractSignedAt IS NULL`, `status='active'`).
2. Войти в кабинет `chestnye-mastera.ru/cabinet`, вверху нажать плашку **«Подписать договор»**.
3. Подождать 10+ секунд на шаге «Договор» — страница **не должна** никуда уводить.
4. Пройти шаги: прочитать → ввести данные → загрузить 2 фото паспорта → «Подписать».
5. Увидеть экран «Договор подписан!» — он **не должен** мигать редиректом (статус стал `pending_contract`).
6. Активировать мастера в CRM (или перелогиниться — на логине `pending_contract` авто-переводится в `active`). В течение ~8с страница сама уведёт в `/cabinet/orders`.

## Alternatives

| Вариант A — убрать редирект целиком (как в старом master-pwa) | Вариант B — гейт по шагу визарда (`step === "done"`) |
|---|---|
| **За:** максимально просто, точная копия старой логики; ноль риска нежелательного редиректа. | **За:** тоже чинит баг — незалогиненный по договору мастер на шаге `read` не редиректится. |
| **Против:** мастер, подписавший договор и активированный, не будет автоматически уведён в кабинет — придётся жать «Ожидать подтверждения» вручную; теряется задуманный в новом кабинете UX авто-перехода. | **Против:** хрупко — `step` это клиентское состояние из `sessionStorage` и зависит от порядка эффектов. `contractSignedAt` — серверная истина, надёжнее как признак «договор реально есть». |

Выбран guard по `contractSignedAt`: он опирается на серверный факт и сохраняет полезное авто-поведение нового кабинета.
